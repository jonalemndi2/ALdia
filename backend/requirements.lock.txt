# requirements.lock.txt — VERSIONES EXACTAS, VERIFICADAS.  Esta es la ruta
# recomendada para instalar en un comercio.
#
#     python -m pip install -r backend/requirements.lock.txt
#
# POR QUE EXISTE ESTE ARCHIVO
# ===========================
# `requirements.txt` declara rangos (`fastapi>=0.115.0`). Eso está bien para
# quien quiera actualizar, pero es peligroso para una instalación productiva:
# el mismo `pip install` que hoy anda, corrido dentro de seis meses, puede
# traer una versión nueva de FastAPI o Pydantic con un cambio incompatible y
# dejar al comercio sin poder facturar un lunes a la mañana. Nadie va a estar
# ahí para depurarlo.
#
# Este archivo fija cada versión —incluidas las dependencias indirectas, que
# son las que rompen sin avisar— al conjunto exacto con el que se corrió la
# suite de pruebas completa: en Windows (el entorno real de instalación) y en
# Linux con Python 3.10 y 3.13.
#
# COMO ACTUALIZARLO
# =================
# No se edita a mano una línea suelta. Se actualiza el entorno, se corre la
# suite completa, y recién si pasa se regenera:
#
#     python -m pip install -U -r backend/requirements.txt
#     python -m pytest tests/ -q          # tiene que pasar TODO
#     python -m pip freeze                # y de ahí salen las versiones
#
# Los marcadores de entorno (`; sys_platform ...`) NO son adorno: uvicorn trae
# dependencias distintas según el sistema operativo y la versión de Python, y
# sin ellos el archivo solo serviría en la máquina donde se generó.
# ─────────────────────────────────────────────────────────────────────────────
